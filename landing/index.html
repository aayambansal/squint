The loop, played straight

Coding agents are already good at writing frontend code. What they lack is taste held constant and a feedback loop that never sleeps. squint supplies both.

❯ make the pricing page feel premium

Every ask ships inside a design brief. Direction before code, design tokens over one-off styles, and a ban list of the patterns that make pages read as machine-made. Seven committable aesthetic directions, or write your own.

✗ error TS2304 → auto-fix 1/2

The dev server is watched. Fresh build errors go back to the engine with the surrounding output and a root-cause instruction, capped at two attempts.

· runtime clean · after every turn

The page itself is checked. After each clean turn squint loads the app headlessly and catches what the server never prints: blank pages, exceptions, failed requests, hallucinated CSS classes.

/undo · /variants · Alt+S

Reversible and explorable. Every ask records a checkpoint, so undo and rewind are one command. Sandbox mode stages whole sessions in a shadow worktree until you apply. Variants build the same ask three ways in parallel. Alt+S pins elements with notes and compiles them into one annotated ask.

It looks at what it built

A dev server can be green while the page is wrong. squint screenshots the result, measures what moved, and makes the agent read its own work.

/review · 390 / 768 / 1440

The agent looks at its own work. Screenshots at phone, tablet, and desktop widths, then a critique of what it can actually see, ranked by visual impact, then fixes.

· visual pulse · <nav.top-nav>

Drift gets named. Every clean turn is screenshotted and compared with the last. LCP deltas and long-frame jank ride along, attributed by function.

▣ .squint/preview/pulse.png

Real pixels in the transcript. On kitty, Ghostty, WezTerm, or iTerm2 the screenshot renders inside the terminal, next to the turn that produced it.

Read the check catalog: what each one catches, and where it surfaces

The engine doesn't grade itself

A loop that presses on failures teaches an agent to make the failures disappear. squint watches for that too, and tells you instead of the engine.

⚠ sentinel · test deleted

Evasion gets caught. Deleted tests, added skips, suppression comments, watered-down checks, touched locks: detected deterministically each turn and reported to you.

/lane on

A second reviewer in fresh context. The review lane reads each turn's diff, not the conversation, so blind spots don't inherit. Three findings at most, ranked by severity, read-only by contract.

/goal <objective>

A standing goal, machine-checked. Auto-fix presses until squint's gates come back clean, because the engine doesn't get to decide when it's done.

/decide · /yes · /no

Decisions keep. They live in a committed ledger the engine cannot silently undo, and ride into every ask. Contested changes pause, with a screenshot, for your verdict.

The same loop, without the TUI

Everything above also runs headless: as a pipeline step, behind MCP, or as a daemon you can walk away from and come back to.

❯ squint serve · squint attach

The session outlives the terminal. The daemon owns the run on a unix socket; attach the full TUI from any terminal or over ssh. A dropped connection no longer kills the work.

❯ squint ci --url … --compare

A pipeline step with an honest exit code. Gates, page audit, flow replay, a JSON report, and a digest-sealed receipt tying green to the exact pixels. Compare fails the run on anything that regressed since the last receipt.

❯ squint mcp

The gates as MCP tools. Agents that speak MCP call squint's verification directly, instead of squint wrapping them.

❯ squint flows export †

Journeys become Playwright specs. A flow is six readable lines that squint replays headlessly every turn. Export writes the same journey as a spec that runs under the e2e gate, in CI, and on your teammates' machines.

Bring your own agent

squint drives whichever of these is on your PATH, through one normalized event stream. Streaming, session resume, and cost tracking wherever the engine supports it.

Run it

One engine on your PATH is enough. No cloud project, no lock-in, no secrets stored: API keys stay wherever your agent CLIs already read them.

Start from nothing

❯ npx @aayambansal/squint init my-app
# Vite + React + Tailwind, tokens first
❯ cd my-app && squint

Or on any existing repo

❯ npm i -g @aayambansal/squint
❯ cd your-project && squint
# /dev · /review · /check · /undo
